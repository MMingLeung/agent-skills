# 用词与句式规范

从本人 2025–2026 年的 10 份操作手册、说明书和成果报告中归纳。主流程见 [../SKILL.md](../SKILL.md)。

## 1. 通用口吻

- 写给业务人员看，不写给开发者看。说“点哪里、选什么、得到什么”，不解释实现原理。
- 主语：操作手册、说明书用“本工具 / 本程序 / 系统”；成果报告用“本案例”。不用“我们”“您”“用户”。
- 一句只讲一件事。一个步骤超过两个动作就拆开。
- 不用营销和情绪化措辞：温馨提示、恭喜、哦、点击这里、立即开始。

## 2. 固定句式

| 场合 | 句式 | 原文示例 |

| 准备数据 | 准备“××”Excel 文件。/ 准备“××”文件夹，里面放好……。 | 准备“网专项技术资料目录”文件夹，里面放好对应的技术资料。 |
| 启动 | 双击“main.exe”启动程序。 | 双击“源代码/RegulatoryAutoEntry/启动程序.bat”启动程序。 |

## 3. 步骤动词

步骤一律动词开头：准备、双击、选择、点击、填写、粘贴或拖拽、勾选、确认、核对、查看、等待。

- 按钮：点击“开始”按钮。/ 点击“执行”开始处理。
- 下拉框、TAB：选择“投资项目录入” TAB。/ 在“运行模式”中选择“打包”。
- 输入框：在“下载根目录”中填写保存位置。/ 在“Excel 路径”中粘贴或拖拽“退回模板”Excel 文件。
- 收尾：等待程序执行完毕。/ 在“已处理台账”文件夹中查看结果。

## 4. 引号和名称

- 界面上看得见的东西（按钮、TAB、输入框标题、下拉选项、弹窗按钮）、文件名、文件夹名、表头，一律用中文引号“”包裹，**名称必须和界面、源码一字不差**。
- 引号必须成对、方向正确：写成“main.exe”，不写成”main.exe”（左右都是右引号）。
- 文件类型照常写：Excel 文件、PDF、DOCX、ZIP 压缩包。统一写“Excel”或“EXCEL”，同一份文档内保持一致。

## 5. 安全边界（涉及网页录入、提交、发布时必写）

- 写清程序做到哪一步为止：程序不自动提交或发布。
- 写清“完成”的含义：出现“生成完成”只表示本次任务已准备好；完成录入不等于已保存或已提交。
- 写清人工核对项：核对候选人数量、排名、单位名称、报价……确认无误后再由人工提交。

## 6. 说明书的“技术栈说明”

- 每个依赖一行：名称 + 版本（有就写）+ 一句话用途。
- 用途写“在本程序里干什么”，不写百科介绍。

| 写法 | 示例 |
|---|---|
| 好 | DrissionPage：用于接管浏览器并执行网页自动化操作，包括打开页面、输入目录号、点击按钮和下载文件。 |
| 坏 | paddleocr：这是一个由百度开发的、基于 PaddlePaddle 深度学习框架的超轻量级且实用的 OCR 工具套件。它封装了文本检测、方向分类和文本识别等功能…… |

## 7. 成果报告 / 案例材料

- 主语“本案例”；单位第一次出现写全称，后加（以下简称“××”）。
- 先讲痛点，再讲做法，最后讲成效。做法写成“一是……；二是……；三是……”。
- 常用转变句：“推动……由'××'向'××'转变”。适度使用，一节不超过两次。
- 成效必须给数字和口径：截至××年××月底，单个项目人工成本为 0.46 万元，较 2024 年降低 40.48%。
- 成效数据同时出现在正文和“表N 案例实施成效”里，两处数字一致。
- 附加材料列成“附件1：《……》”清单。
