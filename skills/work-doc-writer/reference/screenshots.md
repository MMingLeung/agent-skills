# 截图对照、标注与插入

用户会指定一个截图文件夹。截图通常没有规律的文件名，需要逐张看图后对应到文档位置。

## 1. 流程

1. **列出截图**：`annotate.py grid <截图文件夹>`，每张生成带坐标网格的副本（`_grid/*.grid.png`），并打印尺寸。
2. **逐张看图**：用 Read 打开原图和网格副本，判断是哪个功能、哪一步、要框哪些控件，读出框的像素坐标。
3. **写清单** `shots.json`（放在源稿旁边），然后 `annotate.py table shots.json` 输出对照表。
4. **用户确认（硬门禁）**：把对照表发给用户，确认后才标注和生成。用户改了就改清单再出表。
5. **标注**：`annotate.py apply shots.json`，输出到 `output_dir/<id>.png`。
6. **逐张复核**：用 Read 打开每张标注图，检查下面第 4 节的清单，不合格改坐标重画。
7. **插入**：源稿里写 `![图1-2 ××展示图](shots/annotated/1-2.png)`，放在对应步骤之后。

文件名带编号（如“2-3 点击执行.png”）时按编号对应，但仍要出对照表给用户确认。

## 2. shots.json

```json
{
  "source_dir": "E:/项目/截图",
  "output_dir": "annotated",
  "shots": [
    {
      "file": "微信截图_20260415.png",
      "id": "1-1",
      "section": "打包功能 / 操作步骤 第2–5步",
      "caption": "图1-1 打包功能操作界面图",
      "marks": [
        {"box": [118, 118, 377, 152], "label": "1、选择运行模式"},
        {"box": [0, 22, 50, 72], "label": "2、点击开始", "pos": "right"},
        {"text": "按实际情况选择", "at": [420, 300]}
      ]
    },
    {"file": "运行日志.png", "id": "1-2", "section": "打包功能 / 结果说明", "caption": "图1-2 打包结果日志图"}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `source_dir` / `output_dir` | 原图目录 / 标注图目录；相对路径以 shots.json 所在目录为准 |
| `id` | 图号去掉“图”字，输出文件名就是 `<id>.png` |
| `section` | 放在哪个功能的哪一步，给用户确认用 |
| `marks[].box` | 红框 `[左, 上, 右, 下]`，原图像素坐标 |
| `marks[].label` | 框旁红字；只写数字时用大号数字 |
| `marks[].pos` | `auto`（默认：在框四周挑最空白、不压其他标注的位置）/ `top` / `right` / `bottom` / `left` |
| `marks[].label_at` | 手动指定红字左上角坐标 `[x, y]`，自动位置压住界面内容时用 |
| `marks[].text` + `at` | 不带框的红字说明，`at` 是左上角坐标 |
| `crop` | 可选，标注后裁剪 `[左, 上, 右, 下]`，用于去掉无关的桌面区域 |
| `line_width` / `font_size` | 可选，默认按图宽自动计算 |

没有 `marks` 的截图原样复制，用于展示运行过程。

## 3. 标注规范（沿用原手册）

- 红色矩形框（RGB 230,27,27），只描边不填充，框住要操作的控件，四边留 4–8 像素空隙。
- 框旁红字默认写“序号、短动作”，如“1、按需选择录入环节”“2、点击执行”。序号和本节操作步骤的顺序一致。
- 控件很密、放不下文字时只写序号“1”“2”，说明放正文。
- 需要提醒时加一句不带框的红字，如“按实际情况选择”。
- 不用箭头、圆圈、马赛克、阴影。纯展示过程的截图不标注。
- 截图里有账号、密码、身份证号、手机号等敏感信息时，先告诉用户，由用户决定是否裁掉或重截。

## 4. 复核清单（每张标注图都要看）

- 红框完整套住目标控件，没有偏移、没有切掉文字。
- 红字没有压住要看的内容，深色背景上也能看清。自动位置可能落在空白输入框里，看起来像在标注那个输入框，发现就改 `pos` 或 `label_at`。
- 贴着窗口边缘的工具栏按钮四周没有空地，直接用 `label_at` 放在按钮右下方，必要时调小 `font_size`。
- 序号顺序和正文步骤一致，没有跳号或重号。
- 图号、图题和清单一致；图题说明“这是什么图”，如“所需资料展示图”“录入关键节点展示图”“程序录入完成页面图”。

## 5. 图题写法

- 格式“图{功能序号}-{序号} 描述”，序号与描述之间空一格；功能序号按“操作说明”下的二级标题顺序。
- 成果报告用“图1 描述”连续编号。
- 常用描述：××所需资料展示图、××操作界面图、录入关键节点展示图、手动登录页面图、前往指定页面图、程序录入完成页面图、结果文件展示图。
