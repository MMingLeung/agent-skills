# 政务 / 企政 GUI 设计规范

面向政务系统、事业单位内部系统、公共服务平台和企业政务类后台。完整 token 见 [tokens.md](tokens.md)；组件与文案细则见 [reference.md](reference.md)。

## 何时用 / 不用

| 用 | 不用 |
|---|---|
| 管理后台、办事大厅、审批流、档案/材料台账 | 营销落地页、作品集、品牌宣传站 |
| 表单、表格、查询、状态反馈、任务办理 | 消费型大卡片堆叠、霓虹渐变、玻璃拟态 |
| 用户要「政务感 / 正式克制 / 蓝白灰」 | 纯动效/组件手感打磨（交给其他设计 skill） |

## 核心硬规则

1. **未指定主题色 → 主色 `#0A4CB5`**（主按钮、当前菜单/Tab、选中/焦点、主链接、关键图标、单序列图表）。已指定颜色则遵循指定值，不强制覆盖。
2. **语义色不替代主色**：成功绿、警告橙、错误红、禁用灰；不要把整页文字/边框都刷蓝。
3. **视觉克制**：少渐变、少阴影、少大圆角、少装饰图形；层级靠字号/字重/间距/边框/浅底。
4. **信息密度**：中等偏紧凑，优先办理效率，不做营销式大留白。
5. **文案短直**：能短语不写长句；禁营销/情绪化/拟人化措辞。

禁止：玻璃拟态、霓虹渐变、发光边框、超大圆角、悬浮消费卡片、复杂装饰背景。

## GUI 文案（必守）

1. 能用 2–6 字就不要完整长句；一区尽量一条关键提示。
2. 按钮用动作词，通常 **2–4 个汉字**（查询 / 重置 / 新增 / 保存 / 提交 / 导入 / 导出 / 删除 / 确认 / 取消 / 办理 / 审核 / 通过 / 退回…）。
3. 字段旁已有标题不重复；常识操作不加废话说明。
4. 错误直接说问题与处理；成功只报结果；复杂规则用「说明」折叠。
5. 不堆「温馨提示」「友情提示」；高风险操作要简短确认（如 `删除后不可恢复，确认删除？`）。
6. **主表单区不要挂长流程说明小字**（如 WPS/OCR/镜像/失败策略等实现细节）。流程写日志、手册或 handoff；界面只留路径/操作控件，保持简洁。

推荐 / 避免对照与完整按钮表 → [reference.md](reference.md#gui-文案细则)。

## 布局与页面

桌面推荐：`顶部栏 + 左侧导航 + 主内容区`。

主内容区顺序：面包屑/标题 → 查询 → 工具栏 → 表格或表单 → 分页/操作。

| 区域 | 要点 |
|------|------|
| 查询 | 简单单行；多条件 2–4 列；非核心进「更多条件」；末端 `查询` / `重置` |
| 表单 | 标签短；必填统一标识；错误紧邻字段；分组用分区标题/浅底/细分隔，不靠堆卡片；控件高默认 36px |
| 表格 | 浅灰表头；行高约 40px；关键列可固定；操作列右侧；数值右对齐；Hover 极浅蓝；忌明显斑马纹 |

不要把每一块都套成独立大卡片。细节 → [reference.md](reference.md#布局与组件)。

## 组件速记

- **主按钮**：`#0A4CB5` / 白字 / 高 36px / 圆角 4px；同区通常只一个主按钮
- **次按钮**：白底 + 蓝或深灰字 + 1px 边框 / 圆角 4px
- **输入**：高 36px / 圆角 4px / 边框 `#D8DEE8` / Focus `#0A4CB5`；禁厚内阴影与胶囊输入
- **卡片**：白底 + 1px 边框 / 圆角 6px / 垫 16px；默认可无阴影
- **Tabs**：当前项蓝字 + 底边 2px；大面积胶囊 Tab 仅用于小筛选
- **Modal**：圆角 6px；提示 1–2 行；底按钮靠右
- **状态标签**：短词（待审核 / 已通过 / 已退回…）；轻底深字，忌大面积高饱和实心
- **空状态**：`暂无数据` / `未查询到结果`（禁「空空如也」类）

完整尺寸与状态色 → [tokens.md](tokens.md)；示例 → [reference.md](reference.md)。

## 输出门禁（生成界面时逐条过）

1. 未指定色 → `#0A4CB5`；已指定 → 不覆盖。
2. 现代政务风，不做 Airbnb/Apple 营销页式大留白与消费大圆角。
3. GUI 文案精简；无必要不加副标题、说明段、帮助文字、装饰卡；**禁止**在路径/表单区堆多行灰色流程说明。
4. 主界面突出业务与操作，不是品牌秀；数据页优先表格/筛选/状态效率。
5. 圆角默认 4–6px；阴影轻或无；页底 `#FFFFFF` / `#F5F7FA`。
6. 图标/边框/辅助字用中性灰，避免全页蓝色化。
7. 弹窗与提示优先 1–2 行；删除/作废/退回等须明确确认且文案仍短。
