# 就绪信号与动态内容（通用）

适用：多 TAB 详情页、侧栏/卡片列表、右侧表单、loading 遮罩、多条记录循环。站点特定选择器放在 `sites/<站点>/`，本文只给判定方法。

## 1. 分层就绪，不混为一层

```text
层 1  导航/页签激活   active class、URL hash、tab 高亮
层 2  列表/侧栏       卡片数量 + 首项标题（轻量签名）稳定
层 3  业务区          表单 label、只读字段、表格数据行可见
```

硬规则：

- **截图、入库、回读字段以层 3 为准**；层 1、2 只能辅助。
- 入口落地只要求层 1 + 层 2 稳定即可进入下一动作，不要在入口强求层 2 内容等于目标业务名。
- 切到目标 TAB 后若层 3 未出而层 2 已有卡片，可点首项触发加载，再 poll 层 3。
- 层 3 已可见时，不得再被层 2「首项不像本 TAB」阻塞到超时。
- 日志区分：`页签未激活` / `列表未刷新` / `业务区未渲染` / `假 loading 拦截`。

## 2. 内容信号，不用激活态或日期

切 TAB / 切记录后置条件必须含**业务内容**：

- 目标区域标题命中本 TAB 关键字；或
- 标题集合相对切换前发生变化；或
- 目标 TAB 右侧表单/只读区出现。

禁止：

- 仅 `sleep(0.8)` 当切换成功；
- 激活后内容未变仍采集；
- 用「日期是否变化」当唯一刷新条件（不同记录日期相同是合法的）；
- 「输入框仍非空」当记录已刷新。

连续稳定 N 次（按 `poll`）后才采集；超时先重试点击一次，仍失败则跳过并记**区分备注**（丢失 frame / 列表未刷新 / 其它），禁止入库串数据。

## 3. 只采实际存在的项

```text
读取可见 TAB / 记录文案列表并去重
→ 按已知业务顺序排列，未知项追加在后
→ 缺失的固定项跳过，不记「未找到」失败行
```

禁止用「每条记录都应该有的完整枚举」硬遍历。

## 4. 假 loading（容器壳 ≠ 真转圈）

很多 UI 库的 loading 容器（如 `*-nested-loading` 一类的外壳）长期 `is_displayed=True`，但真正阻塞的是内部转圈层或可见遮罩。

```text
blocking_loading(scope):
  仅当存在 可见的 转圈元素（如 *-spinning）
  或 可见的 遮罩（如 *loading-mask 且 style 非 display:none）
  返回 True

panel_ready(scope):
  先检测层 3 业务内容
  若层 3 已 True → 直接 ready，忽略容器壳
  否则再判 blocking_loading
```

修改 loading 判定前，先在 live 浏览器跑一遍：容器壳数量、转圈数量、业务字段数量，三者一起看。

## 5. 每轮重取作用域

多条记录循环时：

```text
for 每条记录:
  回到列表（必要时导航）
  frame = 重新 get_frame(...)      # 禁止沿用上一条记录详情页的 frame
  写搜索框 → 回读 value
  点查询 → 等行集合变化或仅剩命中行
  进入详情 → 重新 get_frame
```

症状：第 2 条起搜索框空、列表未过滤、截图仍是上一条。根因几乎都是对过期 `frame` 调 `ele/input`。

## 6. 列表 vs 详情

详情页也可能带搜索框。判断「已在列表」须同时满足：有列表搜索框 **且** URL 不含详情特征 **且** 无详情 TAB 条（或有列表专有元素）。已在列表时不要无条件重新 `tab.get(列表URL)`。

## 7. 轻量签名

settle 阶段用「数量 + 首项标题（+ 日期）」做签名，不要每 300ms 全量深挖整表；全量读取只在签名稳定后做一次。
