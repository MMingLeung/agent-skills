# DEMO 开工卡（口头需求 → Cursor 可开干）

## 目标
把当面口头/几条要点收成**一张短 DEMO 开工卡**，直接丢进 Cursor 第一轮出可演示草稿。
本 Skill 只产出这张卡（或按卡开 DEMO），不定技术栈长 PRD、不替用户对业务承诺工期/报价、不自动改生产。

对齐关系：字段语义对齐「需求收集卡」，但交付物压成四块短卡，专给「马上做 DEMO」用。完整交接仍可用八节「需求收集卡」。

## 何时用
- 用户刚跟业务口头对接完，要进 Cursor 做 DEMO
- 用户贴了 3～8 条要点，或已压好的开工卡
- 用户说「开工卡」「口头需求」「少写长 prompt」「按卡做 DEMO」

## 硬性规则
1. 缺字段写 `待确认`，**禁止瞎编业务规则、系统名、字段口径**。
2. 最多向用户确认 **1 轮**（一次打包 ≤3 个缺口）；能默认的写入「假设」并标明。
3. 钱、提交、删除、发正式通知、改生产库 → 写入「人拍板与禁止」，默认 DEMO **只读 / 本机 / 测试样例**。
4. 登录账号、验证码、正式提交仍由用户本人操作。
5. 代码与数据默认不出公网；无明确授权不写生产、不代发业务消息。

## 输入（二选一）
A. 3～8 条要点（口语即可）  
B. 已压好的【DEMO 开工卡】全文（则校验四块是否齐全，缺的补 `待确认`）

## 交付物模板（原样填）

```text
【DEMO 开工卡】
背景一句：

输入 / 输出：
- 入：
- 出：

人拍板与禁止：
- 
- 

成功标准：
- DEMO：
```

### 四块怎么填（对照需求收集卡）
| 开工卡 | 对应需求收集卡 |
| --- | --- |
| 背景一句 | §1 背景与谁用（场景+痛点压成一句） |
| 输入 / 输出 | §2 输入 + §3 输出 |
| 人拍板与禁止 | §4 黄/红人核 + §5 禁止事项 |
| 成功标准 | §3 成功长什么样 + §6 验收样例（DEMO 粒度） |

## 执行步骤
1. 读用户要点/旧卡，先填能填的格。
2. 空缺：能合理默认的写入假设；真正只有用户知道的放进缺口（≤3）。
3. 若用户只要「出卡」：只交开工卡 + 一句「下一站：丢 Cursor / 说动手开 DEMO」。
4. 若用户要「按卡开 DEMO」：以开工卡为唯一范围；缺关键格先问一轮；开 DEMO 时：
   - 先复述范围与禁止项（各一行）
   - 只做成功标准里的 DEMO 验收路径
   - 越界需求标「超出本卡」并停，不擅自扩 scope
5. 失败时落证据（报错摘要 / 截图路径 / 复现步骤），不静默重试写操作。

## 样例（监管网发布时间台账）

要点：
「要批量导出监管网各节点公示发布时间；现在一个个点页面抄；要 Excel；本机跑别动生产；先 DEMO 导出一页样例。」

压成：

```text
【DEMO 开工卡】
背景一句：监管网各节点公示发布时间，从手工抄改为本机批量导出 Excel。

输入 / 输出：
- 入：已登录可访问的监管网项目列表（或你指定的几个样例项目）
- 出：Excel 台账（节点名、发布时间、关联凭证链接/截图路径）

人拍板与禁止：
- 只读抓取 + 本地导出；禁止在生产库改数、禁止代点「提交/发布」
- 登录账号与验证码仍由你本人操作

成功标准：
- DEMO：选 1～2 个样例项目，能导出一页表，列齐全、时间能对上页面；业务点头即可进下一版
```

## 调用方式（给人看）
在 Cursor Agent 输入：`/demo-kickoff-card` 然后贴要点；或 `@demo-kickoff-card` + 要点。
要直接开 DEMO：贴已填好的开工卡，并写「按开工卡做 DEMO，缺字段标待确认不要猜」。
