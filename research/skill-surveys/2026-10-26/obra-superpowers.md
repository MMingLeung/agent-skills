## 2. 它是什么

superpowers 是一套给编程代理用的开发方法，外加一组会自动触发的技能。README 把基本流程写成固定顺序：先 brainstorming 把需求问清并复述，再隔离工作区，然后 writing-plans 拆任务，接着由子代理或当前会话执行，期间用测试驱动开发，任务之间做代码审查，分支收尾时再验证。另有 using-superpowers 负责在会话开始时提醒先找技能。

2026-10-26 的 `skills/` 下有 15 个技能目录。和本库对照时，主要看 brainstorming、writing-plans、verification-before-completion、writing-skills。其余是 git 工作树、并行子代理、调试和代码审查，属于通用软件工程，不是政务交付步骤。

## 3. 写法特点

- 每个技能独立目录，frontmatter 为 `name` 加一段 `description`。description 用 “Use when …” 写时机。verification-before-completion 的时机是「准备声称完成、已修复或已通过，以及提交或开 PR 之前」。
- using-superpowers 的 description 要求在任何回复之前先找到并用上技能，澄清问题也不例外。这是强触发，用来防止模型跳过方法直接写代码。
- verification-before-completion 用一条硬规则卡住完成声明：没有本次新跑出来的验证证据，就不能声称完成。门禁分成找出能证明的命令、完整执行、读输出和退出码、再决定能否下结论。文中另有常见失败、借口清单。
- brainstorming 要求先看已有材料，再提问，把理解复述给用户改，按规模决定是聊天里说定还是写成可供实施的设计说明。
- writing-plans 假定已有通过的设计。任务拆小（README 写的是大约 2 到 5 分钟一件），并要求写明文件路径、实现内容和验证步骤，再交给执行技能。
- writing-skills 把写技能比作测试驱动：先有会失败的检查，再写技能，再收紧。技能分成手法、模式、参考资料三类，并讨论怎样写才不容易被模型用借口绕开。

## 4. 原理与设计意图

这套仓库假设模型会跳步：没问清就写、没跑就说通过、有了技能也不调用。所以它把方法做成默认必经路径，而不是建议。

硬规则和「借口清单」是同一意图：只写原则时，模型会用「这次情况特殊」绕开；把绕开的说法先写出来，并规定看到就停下。验证必须是当次、完整命令的输出，是为了避免拿旧日志或单测通过代替现场结果。

writing-plans 把任务写到含实现要点，是为了让执行阶段少重新设计。代价是计划很长，而且和「先有设计」绑在一起，不适合口头的小 DEMO。

## 5. 对照本库

本库已有开工、实施、收工、交接四段，不是从零补一套软件工程方法。superpowers 里能对上的是开工前问清、收工前拿证据。

### 可借鉴

- `dev-review-verify` 与 verification-before-completion 同向：pytest、同步成功、探针文本都不能代替打开本次产物。可在该技能里保留并写清「常见借口」短表，每条对应应看的证据（页面、导出文件、启动窗口），不另起一套英文门禁口号。
- `demo-kickoff-card` 已要求开做前复述范围和禁止项各一行。brainstorming 的「先复述再改」可以维持在这一行，不必升级成设计文档。
- `writing-skills` 对「技能会被绕开」的处理，可用于 `drission-crawler` 的禁止清单：每条禁止旁边写明对应的停手条件（例如未回读值就不进入下一步）。站点包继续放在 `references/sites/`。
- 收工顺序保持「单测可先做，LIVE 在最后」。这与「证据先于完成声明」一致，用本库已有的三行收尾即可。

### 不要照搬

- 不采用 using-superpowers「任何回复、包括澄清问题之前都必须先调用技能」。`demo-kickoff-card` 允许最多一轮、一次打包的确认；浏览器登录和正式提交仍由使用人操作。强行先调用会挡住这轮确认。
- 不把 writing-plans 的细任务（含实现内容和很短工时）写进开工卡。开工卡只有背景、输入输出、人拍板与禁止、成功标准四块，目的是进 Cursor 做 DEMO，不是替代实施计划。
- 不把「每任务一个新子代理、红绿重构、工作树」写进 `drission-crawler` 或 `windows-gui-bat-launcher`。这两项的验收是真实浏览器回读和窗口就绪，不是通用代码审查链。
- 不把 superpowers 整库安装进本仓库当作产品技能。它服务通用编程会话，和招标站点包、政务文案规范不是同一范围。

## 6. 一句话建议

收工技能继续坚持「没有当次证据就不写完成」；开工卡保持一页四块，不改成带实现细节的编程计划。
